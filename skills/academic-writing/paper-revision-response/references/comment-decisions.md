# 识别审稿意见与确定修改路线

## 先解决的五个问题

1. **意见到底说了什么？** 保留完整英文原文与原编号，配完整中文译文；分清审稿人陈述、询问、建议和 Agent 推断。一个例子可能代表对整个方法的一类担忧。
2. **一条意见有几个独立问题？** 逐个梳理依赖；一条问题拆成几个内部工作项可以，但最终答复仍对应原编号。
3. **论文已写了什么？** 定位原稿的准确版本、章节和段落。术语出现 ≠ 概念讲清；“作者知道” ≠ “读者能找到”。
4. **需要什么类型的证据？** 定义与实施细节、实验依据、统计推断、通用性、成本、人工标注属于不同问题。
5. **最小必要处理是什么？** 明确无需改稿的回复、局部澄清、正式增加信息、再计算、补实验、缩小主张；陈述具体依据，保留作者决策。

## 处理分支

| 实际发现 | 优先路线 | 不可误判为 |
|---|---|---|
| 原稿已直接明确回答 | 引用准确位置，在回复中解释 | 必须给正文加一个重复段落 |
| 原稿有材料但指代不清或分散 | 局部整理，再给位置 | 方法缺失或必须新增实验 |
| 方法与过程确实缺少关键信息 | 补足最适当章节的说明 | 在正文写“为回应审稿人” |
| 原始输出存在、仅缺分析 | 核实来源和口径，补充计算 | 重新运行完整系统才算回应 |
| 证据不足以支撑主要主张 | 设计必要实验，或缩小主张范围 | 使用语言技巧掩盖证据缺口 |

## 控制观点与主张

- 不把对某个参数的使用日志当作其他参数也有效的实验。
- 不把某个公开基准的惯例当作当前研究有效性的证明。
- 不根据审稿人的态度、身份、投稿难度、期刊声誉论证科学问题。
- 重要的不同处理路径，用“实际要回答的问题—已有证据—成本与影响”解释，避免一次塞入十多个无关方案。
- 单条评论若同时提到范围与模型公平性，不能只回应范围就宣布整条完成。

## 优先级与依赖

先统一会改变其他部分的证据或评分口径，再修改 Result、图表、Abstract、Response。已明确且独立的语言与排版改动可以并行。作者调整方向时只更新受影响的内容和依赖，不要重开已确认的问题。

## 建议的轻量呈现方式

**审稿人关注点：** 用具体中文解释完整问题。

**论文现状：** 当前版本与具体章节／段落；已解释与仍缺失的内容。

**证据判断：** 哪些事实已核实，哪些需要数据或作者决策。

**建议处理：** 对普通读者的收益、修改涉及范围、可选方案的实际差别。

**待确认：** 作者尚未授权的实验、结论、文本与文件变更。
