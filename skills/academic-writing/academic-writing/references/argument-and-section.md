# 论证设计、章节职责与公开论文范例

在新建章节、调整段落顺序、论文动机不清或出现论证断裂时读取。单纯局部语法纠错无需启动完整章节规划。

## 一、按读者问题确定章节职责

| 章节或功能 | 读者需要知道什么 | 写作动作与错误边界 |
| --- | --- | --- |
| Abstract | 问题、具体做法、主要证据和最重要结论 | 压缩研究故事，避免写成目录；不增加正文未证实的新主张 |
| Introduction | 为什么存在值得解决的具体问题，为什么当前方案必要 | 具体场景/事实→最近工作的相关缺口→方案→贡献与证据；避免漫长的技术发展史 |
| Background / Motivation | 理解论文所必需的概念和事实是什么 | 用少量可靠实例展示困难与技术条件；避免与研究问题无关的教科书介绍 |
| Related Work | 已有方法与本文是什么关系 | 按研究任务和技术机制比较近邻方案；指出适用条件与具体区别，不逐篇摘要 |
| Method / Approach | 机制如何应对问题，怎样执行 | 解释动机、设计决定、输入/输出、状态、算法、接口、必要参数、假设；不只罗列代码模块 |
| Evaluation / Setup | 为什么这些实验足以检验所声称的贡献 | 解释 RQ、基线、公平比较、数据、指标、配置、分析单位、失败处理与可复现条件 |
| Results | 每个 RQ 的观察答案是什么 | 直接陈述结论及其比较条件，再给关键数值、误差与解释；不逐格复读图表 |
| Discussion | 多项结果合起来支持什么认识 | 提炼机制、代价、条件、反例与实践含义；不重复 Results |
| Threats to Validity | 哪些重要的有效性威胁经过缓解后仍然存在 | 有重点地交代实际威胁、缓解措施与剩余影响；不写礼节性全面自我否定 |
| Conclusion | 最后应记住什么 | 回到问题、机制、核心证据和边界；不增加新实验或新承诺 |

表格按学术论证功能组织，不强制论文采用这些标题或全部章节。方法论文、实证研究、系统论文和工具论文可以合理合并或重新组织这些功能。

## 二、内部 Rhetorical Map（论证图）

复杂新写作先在内部建立下列关系；只对局部编辑时取相关部分。不是一份必须另存的文件。

```text
观察到的具体问题──[数据或复核来源]──►问题重要性
              │
              └──►最近工作的局限──[机制或证据比较]──►研究空间
                                               │
问题/限制──[设计理由]──►方法机制──[应检验的预测]──►RQ/实验
                                                       │
                                               观察结果与不确定性
                                                       │
                                              允许的结论与适用范围
```

每段记录三个信息即可：本段要回答的读者问题；支持它的事实、引用或机制；下一段与它的因果、限定、比较或递进关系。仅将“首先／然后／值得注意的是”插入两段之间不能形成逻辑关系。

**断裂处理**：事实足以支持主张，则说明推导；缺证据时回到权威来源或请作者提供；研究尚未验证时标为待证；无法支持的主张应经作者确认后收窄。不要通过改写句式把缺口掩盖掉。

## 三、三类常见段落与阅读逻辑

- 问题段：具体任务及条件→可观察障碍→障碍为什么影响目标。障碍必须是真实研究问题，不依赖制造式的“以前都不行”。
- 方法段：现有机制在特定条件下的不足→本方法的设计选择→输入/处理/输出→预期效果与约束。能用有代表性的真实例子连接相邻步骤时使用例子。
- 结果段：限定范围内的直接答案→少数改变判断的数值和比较→原因线索与其他解释→与研究问题的关系。

段落不需要固定句数。若所述方法存在输入定义、训练与推理差别、状态更新或复杂系统流程，应保留解释这些信息的必要句子和公式。

## 四、如何研究并使用公开论文范例

在需要建立新的论文叙事、而用户尚未给出足够成型的结构时，阅读少量**研究类型和目标场合相近**的已发表论文，重点检查：

1. 引言如何从具体问题而不是笼统时代背景进入研究；
2. 最近工作的比较如何支持独特的研究位置；
3. 哪些真实观察推动了方法设计；
4. 实验结果如何回答其预设研究问题；
5. 哪些写法具有可迁移价值，哪些是该特定任务的条件性选择。

历史研究中的示例：MultiPL-T 展示了“低资源代码生成问题→直觉替代的实际限制→数据生成和验证方法”的论证路径；《Code Search Is All You Need?》从开发者代码建议的具体任务收窄到代码检索增强；AllianceCoder 先比较检索信息来源，再从观察推导方法。三种路径适合不同研究，不构成固定模板。研究者当前稿件的事实和主张始终优先。

参考论文不得被当作当前工作的实验数据来源，也不得复制原文句子、独特比喻或机械套用段落数；涉及投稿格式时以目标场合的现行规则为准。

## 五、局部写作的收敛条件

如果现有章节已经准确回答读者问题、关键技术信息完整且与相关章节衔接自然，就保留已有内容。新增文字应能指出它补足了哪个事实、推导或理解缺口。不要为展示编辑能力重排已经清楚的论证。
