# 学术论文写作（Academic Writing）

使论文中的问题、最近相关工作、方法机制、评价设计和研究结论形成准确、连续、可核对的论证。以已经确认的研究事实为基础，保留作者的科学立场和必要技术细节。

## 开始：识别任务与已有材料

1. 判断本轮是新写章节、调整论证结构、局部修改、语言精修、压缩篇幅，还是检查全文一致性。**严格遵守用户指定的修改范围**；清楚且正确的原文保持不变。
2. 读取当前稿件与相邻章节、已确认的研究目标和贡献、结果与数据、相关文献、术语/公式、用户已有修改约定。优先使用实际源文件，不让用户重复提供可查事实。
3. 确认本轮允许使用的证据和待决科学问题。来源缺失时标出具体缺口；不得从模型记忆补造数字、引用、实验、方法细节或审稿事实。
4. 根据论文类型和目标读者调整结构。仅当任务涉及投稿格式或官方规定时核查目标会议/期刊当时有效的规则；不自设页数或强制压缩目标。

## 论证组织与写作

1. 按本轮任务规模建立最小内部论证关系：`具体问题与证据 → 最近方案的相关限制 → 方法机制及理由 → 可检验的 RQ/比较 → 结果与解释 → 可支持的主张`。每个重要推导必须有可解释的连接；不为凑模板制造缺口或对立。
2. 为所写章节确定**读者要获得的答案**；为每段安排一个主要论证职责、支撑证据和与上下文的真实关系。按研究类型选择章节顺序，不强制固定段落数。需要细节时阅读 [章节与论证设计](references/argument-and-section.md)。
3. 介绍方法时，解释具体困难、设计决定、输入输出、关键状态、执行流程、假设及其作用；说明必要参数或算法细节，使读者能够判断方法如何实现。设计动机和可复现性不能因篇幅要求而被无依据地删除。
4. 写相关工作时比较最相关方法的任务、机制、信息条件与证据；明确本研究的位置，不把相关工作写成逐篇摘要，也不把检索不到文献当作新颖性的证据。
5. 写结果时先直接回答 RQ，再给能改变读者判断的比较条件、绝对数值/差异、统计不确定性与实际意义。观察到的差异、机制解释和未经检验的推断分别表达；具体做法见 [结果、证据与主张](references/results-and-claims.md)。
6. 讨论真实、影响解释的局限与有效性威胁，把完整分析放在合适的 Discussion / Threats to Validity 位置；本应在 Setup 交代的评价条件仍须如实说明。不要在每项正面发现后机械加入防御性否定，也不要隐藏会改变结论的限制。

## 修订：先论证，再语言

- **内容遍**：核查重要主张与来源证据、术语定义、机制与实验的对应关系、段落推进、重复信息、RQ 的直接回答。发现论证断裂时，选择补充真实证据、收窄主张或标注待核实；不靠润色制造逻辑。
- **语言遍**：用明确的技术主体、动作和对象表达事实；连接词应对应真实因果、比较或条件；删去空泛背景、重复总结、无信息形容词和刻意对偶。保持正式、自然、积极而有依据的论文语气。不要机械套用禁词表。
- **修改幅度**：只做实现目标所需的变更；局部润色不扩大为全文重写。真正改变贡献、方法含义、研究立场、结果解释或主要论证线索时，先提出可核对的差异供研究者决定。

### LaTeX 与交付

- 编辑 `.tex` 时直接操作并交付**可复制的 LaTeX 源码**；保留必要的 `\cite{}`、`\ref{}`、`\label{}`、`\eqref{}`、公式、宏、环境、注释约定和交叉引用。不要把源码退化成普通英文后要求用户自行还原。
- 若任务要求原文/改后对照或双语核对，提供对应的**完整原文与修改后 LaTeX**，以及各自完整中文翻译；不要用省略号掩盖改动。其他任务直接交付用户要求的局部文本或文件，避免固定模板。
- 需要核对具体编辑行为时阅读 [局部编辑与 LaTeX 保护](references/editing-and-latex.md)。内部论证图、检查表和写作过程不默认作为额外文件交付。

## 定稿检查与边界

1. 核查标题、摘要、贡献、RQ、方法、实验、结果和结论之间的主张一致性，以及数值、分母、单位、Baseline 名、图表引用、术语和文献身份；只检查本轮相关范围，不将普通写作升级为全量科研诚信审计。
2. 需要编译时，在当前项目环境中检查 LaTeX 构建或目标段落渲染；如未执行，说明未验证。编译成功不能证明论文论证或研究结果正确。
3. 将实际修订、影响范围、仍需作者确认的**实质性问题**作简短交代。不要声称论文必然符合录用标准、获得审稿人认可或实验已经复现。
4. 当任务转为正式审稿意见分析及回复，交给 `paper-revision-response`；独立科学审稿交给 `independent-paper-review`；需要逐条核对原始数值或引用时再用 `research-integrity-audit`。这些专项能力不要求每次写作同时加载。
