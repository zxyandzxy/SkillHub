# 方法图、实例图：语义、工具和实际预览

## 先确定需要保持的技术关系

方法图在落笔前，应能从论文或已确认设计中定位以下事实：

- 输入与输出的对象和类型；模块执行顺序及真正并行的部分；
- 数据流、控制依赖、调用、反馈和状态转移各自的含义；
- 关键矩阵维度、张量布局、变量、读写方向、共享与复制关系；
- 对照实验中旧方法和新方法的相同条件，以及改变的机制；
- 哪些部分是已实现方法、哪些是待验证的概念性假设。

布局的阅读顺序应与技术因果关系一致。不能因为图形更平衡而添加不存在的反馈箭头、存储组件、Agent 角色或假想数据交换。

## 具体图型

**架构总览**通常展示主要模块、输入输出、关键数据接口。读者无法判断局部机制时，再提供细节放大图。

**运行实例**使用来自论文、真实代码或明确标记的最小教学实例；用稳定对象与标记展示输入如何变化、最终产生什么结果。不能把创作性例子表述为真实实验观察。

**状态演化图**让不变对象留在相同位置，仅强调当前操作、更新对象和前后值；必要时给出时间或步骤编号。

**新旧方法对比**维持相同几何框架、符号、数据规模与细节层级，只展示真实发生的分工、路径或计算变化。例如 FlashAttention-2 Figure 3 将 Q/K/V 的相对位置保持对应，使读者直接看到不同 warp 的分工由 K/V 转向 Q。基线不应被人为绘制得更复杂。

## 工具选择依据

| 工作对象 | 可用工具 | 应保留的源文件 |
| --- | --- | --- |
| 模块与数据流的可编辑排版 | Figma、FigJam、tldraw、draw.io、PowerPoint | 原生设计文件或可导出的可编辑矢量源 |
| 数学、结点和拓扑关系精确的图 | TikZ、Graphviz、SVG | `.tex`、`.dot`、`.svg` 及生成命令 |
| 定量图、矩阵、热力图 | Python / Matplotlib 等 | 原始数据、脚本、环境/参数说明 |
| 简单学术表格 | LaTeX 的 `tabular`、`booktabs`、按需 `siunitx` | `.tex` 和必要的数值源 |

具体工具应服从用户现有环境与交付格式；平台连接器不存在时，不能声称已经在相应软件内绘制。SVG 图标只有在确实帮助识别对象且许可允许时使用，语义清楚的文字和基础形状通常足够。

生成式图像可辅助构思非科学性视觉元素或版式，但精确矩阵、坐标、技术标签和箭头应在确定性工具中重建和核对。

## 可视化修订的交互方式

1. 先完成有真实技术语义的草稿与可编辑源，明确尚待研究者确认的事实。
2. 将图形导出成用户能实际查看的 PNG、SVG 或 PDF；LaTeX 表格先实际编译后展示。只有画图代码和语言描述时，不声称已完成视觉检查。
3. 针对用户反馈修改具体的结构、标记、布局和信息缺口，重新导出受影响的视觉内容。除非确有方案取舍，不主动生成大量主题与配色候选。
4. 将最终版本置于实际论文模板，检查双栏缩放、标记可辨、文字密度、图注及正文引用。

视觉预览能支持版面与理解层面的判断；源文件和代码是编辑与复现的依据，两者不可互相替代。
