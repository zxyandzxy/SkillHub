# 数据来源、身份与信息隔离

对于每个数据实例保留稳定 ID、来源 URL/版本/基线提交、原始材料的许可和取得时间，以及清洗、去重、人工筛选与划分结果。原始记录合法可保存时，留可定位的副本和重建程序。

以 [SWE-bench ICLR 2024](https://proceedings.iclr.cc/paper_files/paper/2024/file/edac78c3e300629acfe6cbe9ca88fb84-Paper-Conference.pdf) 为例，每题由真实 GitHub Issue、对应的代码仓库基线和测试关系组成。基准构建需要核查 Issue 与 PR 的关联、测试在修复前失败/修复后通过的语义。仅观察 PR 中修改文件，不足以证明每条任务在给定基线上有效。

训练/开发/正式测试之间的信息可见性要明确到字段与文件：隐藏的参考补丁若通过检索库、生成提示词、公开评估元数据被模型获得，同样构成泄漏。近似重复、仓库 Fork 和后续版本可能跨分区传播同一任务；去重依据应对应科学目标，而不只依据文件名。

来源许可和采集权限独立于技术可达性。公开网页可以浏览，不代表其私有讨论、个人信息或代码片段能够无条件上传外部推理服务。
