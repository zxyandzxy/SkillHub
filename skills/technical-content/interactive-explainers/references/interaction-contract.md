# 交互模型、控制变量和解释目标

## 核心契约

在编写组件前明确：读者疑问、可控输入及其单位与边界、完整状态、更新函数、可见反馈、基线/重置、模型近似、静态解释。只有每次操作可以被解释为技术状态变化，控件才承担必要职责。

## 单一状态来源

形式上可写为 `state_next = update(state, input)`，再由 `view = render(state_next)` 同步生成图形、数值与解释。用两个组件各自猜测结果，会产生数值与可视效果不一致。避免将动画播放时间当成算法的真实物理或统计指标。

## 两种可迁移模式

**可控机制**：让参数改变映射到确定性结果。例如改变卷积核权重，展示结果像素怎样变化。Setosa Image Kernels 用真实权重矩阵帮助建立这一联系。

**反直觉实验**：先说明常见误解，控制其他条件，改变一个关键参数，展示反例并解释不允许的推断。Distill 的 t-SNE 文章体现这一做法。不要把局部可视化的警告推广到所有算法。

## 复杂路径

逐步算法可使用离散时间步或可回放轨迹。状态应可返回；多步机制保持不变对象的位置和符号。滚动叙事只有在滚动进度与机制步骤存在真实对应时才使用，且不能依赖像素位置提供唯一解释。
