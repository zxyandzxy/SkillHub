# 交互式技术解释

使读者能够改变一个具有技术含义的变量，观察真实或清楚标记的简化模型如何响应，并理解相应关系。先定义模型，再实现控件和动画。

## 定义可验证的交互契约

首先说明读者要理解什么、为什么静态解释不足。明确：输入和取值范围、单位、完整状态、状态更新规则、数值及图形输出、重置后的基线、近似和省略、无需交互时的静态解释。字段与示例见 [interaction-contract.md](references/interaction-contract.md)。

## 从技术关系构建界面

1. 先写正确、可独立阅读的静态解释。选择能揭示一个真实关系的最少控件，不添加无意义的颜色、旋转或速度控制。
2. 用一套权威状态计算数值、图形与解释文字，防止两个视图各自维护值而发生不一致。
3. 检查最小值、最大值、无效输入、连续快速改变、重复重置和切换模式。技术不变量在计算层验证，不只依赖控件的视觉限制。
4. 需要解释变量因果影响时，一次优先改变一个因素，提供返回基线的入口；具有随机性的实验控制种子，或明确不可完全复现的范围。
5. 只在空间、时间顺序或状态连续变化本身有教学意义时使用动画；否则优先离散的可读状态。

## 运行验证与可访问性

使用有标签的原生控件，覆盖键盘、触摸、焦点可见性、小视口与减少动态效果设置；重要变化可感知但不应每帧产生噪声。动画停止、脚本失效或静态导出时保留核心解释。检查方法见 [state-validation.md](references/state-validation.md)。

必须在可用的真实浏览器中操作代表状态并核对可见结果，不把静态截图或代码能编译当成交互正确的证据。无法实际运行时如实说明尚未验证。

## 交付边界

交付可运行源文件、必要的模型说明和实际检查结果。真实计算优先；教学近似必须在界面使用处解释，不得冒充完整模型或实测系统。不要使用未经证实的随机动画支持科学结论，不把外部未经授权的数据发给在线服务。

主要交付是连续阅读的报告时使用 reading-first-reports；任务只是编辑科研方法图时使用 research-figures-tables。
