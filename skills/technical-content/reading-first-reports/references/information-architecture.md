# 阅读型报告的信息架构

## 多种进入路径

读者可能从摘要开始，也可能从搜索结果抵达单节，从目录跳到一个表格，或数日后回访某个结论。标题因此需指明实际信息，如“补丁筛选如何改变修复率”，不能只使用“第二部分”或“更多细节”。目录层级应反映论证关系；不要凭视觉尺寸伪造语义标题。

## 从问题到证据

每一节提出特定问题，解释依赖概念，给出方法或实测证据，并说明结论边界。正文段落负责解释推理；列表承载并列项；表格承载多维精确数据；图形承载关系。技术报告不必复制原论文章节目录，改编论文时必须保留数据、模型、基线、范围与证据强度。

## 图表、公式和引用

赋予重要表图稳定锚点，并在正文中使用编号或语义链接。图注应使单独看到图的读者知道它测量什么、采用何种实验条件、数值单位和证据来源。尽量避免“右图”“上方表格”，它们在窄屏重排后可能失效。长代码有独立滚动区或合理换行，公式在缩放时仍可辨识。

## 工具判断

静态 HTML 适用于依赖少的报告；Quarto 适用于可重复的引用、公式和 HTML/PDF 输出；Observable Framework 适用于频繁更新的数据绑定网站。选择现有维护成本最低且能满足交付要求的方案。工具能力不能决定报告的事实顺序。
