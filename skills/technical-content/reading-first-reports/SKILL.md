# 阅读型技术报告

让读者无需现场讲解即可沿标题、正文、图表、来源和交叉引用理解技术事实。先确定内容与证据，再选择 HTML 工具和视觉样式。

## 确定阅读任务与材料

1. 读取用户给出的报告目标、权威材料、受众、更新范围与交付媒介；不把尚未核实的总结写成事实。
2. 判断读者可能从摘要、目录、搜索结果中的深链接或图表引用处进入。确定关键问题、必要术语和证据范围。
3. 对改写任务保留原报告有效的章节与引用；局部修订不自动扩大为整站重建。

## 组织连续正文

- 先写可信摘要、能够表达内容的标题和稳定章节结构；每节解决明确问题，概念在依赖其解释之前出现。
- 用连续段落承载推理，只有存在真实并列关系时才使用列表；多维精确比较用表格，结构和趋势使用有来源的图形。
- 给重要图表、公式、案例和章节建立稳定锚点；图注交代对象、单位、条件及来源；引用链接到可核查原文。
- 不把每段包装成卡片，也不按幻灯片固定宽高排版；按正常阅读行宽设计响应式正文。

对较长报告的目录、深链接、图注和证据组织读取 [information-architecture.md](references/information-architecture.md)。

## 实现与交付

1. 优先使用具有语义结构的 Markdown、HTML 或现有项目文档系统。多格式、公式和引用有明确收益时可选 Quarto；真实数据绑定应用才考虑更复杂的框架。
2. 保证主要结论、证据、正文目录在 JavaScript 不可用时仍能阅读；交互只增强探索，不能承担唯一的信息入口。
3. 检查桌面与窄屏的正文、代码、公式、图片和宽表；键盘可到达导航与链接，状态信息不只靠颜色或悬停。
4. 请求打印或 PDF 时实际生成并核对分页、图文关系、表头、引用和可辨读性；未能导出或目视检查须明确说明。

交付与降级细节读取 [responsive-and-print.md](references/responsive-and-print.md)。

## 停止与职责边界

交付用户要求的 HTML/Markdown/可打印文件及必要源文件，说明实测的浏览器和格式。完成需要正文论证可独立理解、关键来源可追踪、目录和深链接有效、主要信息在静态出口仍存在。结构校验通过不代表科学事实已核实，也不代表 PDF 已被视觉检查。

普通长篇正文中的导航或折叠功能不足以触发交互解释器；主要按页讲演时使用 technical-presentations。未经许可不外发未发表资料，第三方图片与字体使用须核对权利。
