# 技术演示与论文讲解（Technical Presentations）

先解决观众理解研究所需的知识和论证顺序，再决定是否制作可视化演示文件。逐页内容稿是完整交付形式。

## 选择任务分支

1. 明确是论文讲解、阶段研究进展、专题技术报告、局部修改还是直接制作成品；判断听众与其先备知识、独立阅读或现场讲解、现有模板和用户指定媒介。
2. 论文讲解先读目标论文的任务、方法、实验及必要图表，沿真实引用查少量能解释核心困难的前作。按`实际问题 → 相关技术 → 尚未解决的困难 → 方法机制 → 可信证据`组织理解，不机械按原论文目录配页。见 [论文理解与讲述](references/research-story.md)。
3. 进展汇报使用研究者实际记录建立目标、已完成范围、最新结果、尚未解决的问题与下一步；研究中的计划与已经完成的实验明确区分。
4. 如果用户仅要求逐页文字或已有讲稿，直接产出对应内容；未经明确要求，不启动制作 PPTX/HTML/PDF 的附加流程。

## 先形成可独立阅读的逐页文稿

- 为每页提出具体读者问题或有证据支持的判断；写可直接复制的标题、技术解释段落、必要公式/代码、真实图表来源和阅读说明。
- 对关键概念先解释必要背景，用一个稳定例子和符号贯穿多页。多步算法保持相同对象位置，只突出本步真实状态变化；不要求每页只有一句话。
- 读者需要理解的定义、实验条件、图例和论证必须在页内或相关相邻页面中可获得，不把关键解释留给口头补充。
- 只有讲述范围或科学含义的重要取舍才需作者确认；已明确的内容直接编排。详细页面组织见 [逐页信息设计](references/slide-content.md)。

## 用户要求制作文件时

1. 优先沿用用户现有模板、原论文清晰可读的图表与合法授权的素材。依据媒介选择 PPTX、HTML 或 PDF；不默认使用同一种前端框架。
2. 在真实内容上建立页面的排版系统，保持符号、颜色和字体语义一致。信息密度以独立理解为准，避免大面积无意义留白、装饰卡片和无内容过渡页。
3. 实际渲染并展示代表页、复杂图表页和最终页面；检查遮挡、文字、数学、图例、尺寸、引用以及导航和静态导出。见 [制作、渲染与交付检查](references/render-and-deliver.md)。
4. 原图裁切或重绘不得改变数值、轴、比较条件或允许的结论；截图不能冒充可编辑源。

## 完成条件与权限

在用户指定范围内交付逐页文稿或真实文件，说明数据/图形来源、实际检查与尚未检查的内容。独立阅读应可跟随背景、机制、证据和边界；原始论文和实验主张不能因叙事而被改写。修改论文原图、版权素材或正式研究结论须遵守对应权限。简单任务省略不必要的正式步骤。
