# 收到评审意见后的事实核查

先确认评论描述的代码分支和版本，定位实际行为，检查是否与需求/协议冲突。正确问题按授权范围修复后验证；引用过期代码、误解约束或产生错误推断时，用具体证据说明；关系到新产品决定时请用户选择。

“独立 Agent 审查”有可能减少共用思路，也可能重复相同错误。意见被提出不等于事实成立，拒绝意见也需要依据。评审不授权自动改动、推送、合并或在公开 PR 发表评论。

交付优先展示可操作发现，报告覆盖范围和实际检查；无发现只能描述“所检查的范围内未识别可定位问题”，不能推断生产运行全面正确。

参考：[Superpowers Receiving Code Review](https://github.com/obra/superpowers/blob/main/skills/receiving-code-review/SKILL.md)、[Code Review by Matt Pocock](https://github.com/mattpocock/skills/tree/main/skills/engineering/code-review)。
