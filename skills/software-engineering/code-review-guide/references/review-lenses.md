# 需求符合度与工程质量

需求视角：对照原始目标、验收条件和产品行为，检查遗漏、额外功能和用户可见的回归。实现视角：检查输入、状态、错误传播、数据读写、并发、权限及测试是否能发现真实问题。仅看代码是否“漂亮”可能漏掉需求偏差；只看测试绿灯也可能漏掉不完整断言。

评审必须明确 Git 比较对象：分支相对 merge-base、两个提交之间、暂存区和未暂存区是不同的差异。未跟踪文件没有自动包含在普通 diff 里。远程 PR 也可能在审查期间更新，关键发现应对应准确 SHA。

报告严重问题需有实际位置、触发条件、影响与证据；尚未运行的猜测应标记。安全与权限问题可在适用时检查可信服务端边界，性能问题应查看可比测量，不凭代码外观断言加速。

参考：[Google Engineering Practices What to Look For](https://google.github.io/eng-practices/review/reviewer/looking-for.html)。
