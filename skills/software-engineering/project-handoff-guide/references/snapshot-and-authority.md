# 项目快照与权威来源

## 信息职责

- 需求基线：目标、非目标、验收条件。
- 设计决定：现有架构、权衡与不能随意更改的选择。
- 执行计划：里程碑、依赖与当前批次。
- 当前快照：最新状态、验证、阻塞和下一步。
- Git 和文件现场：真实已经修改/提交/未提交的内容。

这些职责不要求分别创建多个文件。优先沿用项目当前的入口，其他位置使用链接。历史决策被替代时保留生效语境，不让过时结论冒充当前规则。

## 快照字段

任务身份、核对日期、目标/边界、已确认与待决取舍、完成/未完成成果、代码版本和工作区状态、实际验证及环境、调查结论、阻塞/下一步、临时资源和清理责任。无需复制长日志与敏感信息。

## 证据新鲜度

之前的测试成功仅适用于当时的代码、数据、配置和环境。无关修改不必导致全量重跑，影响既有结论的变更才需要重新检查。版本链接和测试记录应能让接手者定位对应对象。
