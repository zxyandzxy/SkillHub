# 项目状态记录与交接

帮助下一位执行者在有限上下文中恢复同一任务，避免重复工作、覆盖未提交修改或把旧计划当作当前事实。

## 先识别真实工作现场

检查当前任务、现有说明、相关进度记录、分支与提交、已修改/暂存/未跟踪文件及必要服务。优先更新项目已有权威入口，不为了套模板新建成套日志。需求、设计决定、执行计划、当前快照和 Git 事实承担不同职责。

## 整理可恢复的快照

按实际需要留下：目标及当前范围、已确认决定和授权、完成与未完成成果、相关文件与分支、实际执行的检查和版本、尚未确认的问题、可靠调查结论、阻塞原因及下一项直接行动。保存状态核对时间，敏感值只提供安全的配置说明而不复制密钥。

需要处理多个会话或旧快照时阅读 [snapshot-and-authority.md](references/snapshot-and-authority.md)。

## 接手与核对

1. 先读项目入口与最新可信快照，确认本次接续的任务身份和主要约束。
2. 核对 Git/文件/数据/测试与记录是否仍匹配；有冲突时以当前现场调查为准，不机械重跑已经有新鲜证据的全部工作。
3. 检查已确认决定的授权范围，不把“建议下一步发布”当成用户已经批准发布。
4. 更新实际状态，继续能够独立执行的已授权工作；真正未决的重大选择才暂停相关步骤。

恢复与离开会话的方法见 [recovery-and-exit.md](references/recovery-and-exit.md)。

## 交付边界

复杂任务采用简短但足够恢复的快照，短任务无需建立记忆库。记录不会替代实际 Git 状态或运行输出；上下文压缩和子 Agent 是可选工具，不假设任何平台能读取内部压缩对象。交接任务不自动授权 git commit、push、发布、清空工作区或删除用户文件。
