# 性能测量与优化

以可复核的测量回答目标任务为何慢、瓶颈在哪里、修改后改善了多少以及代价是什么。没有可比较数据时，只能提出假设和测试方案。

## 确定场景与指标

读取用户目标、代表工作负载、代码与环境。说明任务/操作、数据规模、并发与设备、构建模式和相关指标。按应用选择延迟分位数、吞吐量、帧表现、内存、I/O、能耗等必要指标；不要把单一平台阈值用于所有产品。

## 测量基线与定位

1. 记录代码版本、配置、输入数据、预热、缓存状态、系统资源和测量入口；区分单函数微基准与完整用户路径。
2. 对代表场景进行重复测量，保留分布与波动；需要时报告中位数、长尾分位数和资源峰值，而非只看单次平均。
3. 利用 profiler、trace、指标、日志或精简对照实验寻找真正的关键路径。写出“机制—指标变化”的可证伪假设。
4. 优先做一项可归因的修改，在可比较条件下复测；同时验证行为正确性和资源、复杂度及维护代价。

基线和定位规则见 [measurement-and-profiling.md](references/measurement-and-profiling.md)。

## 分析优化是否值得保留

比较真实收益与缓存一致性、并发争用、预计算、依赖或额外基础设施的成本。小幅改善但显著增加复杂度时，可以撤销或报告取舍；没有显著收益不应包装成“已优化”。详见 [tradeoffs-and-reporting.md](references/tradeoffs-and-reporting.md)。

## 权限与交付

报告场景、版本、测量方法、前后结果及波动、瓶颈证据、改动、正确性复核和未覆盖条件。未经授权不得在生产环境运行可能影响用户的高负载测试。环境不可比或工具不可用时说明限制，不给出虚构加速比。

出现未定位的突然性能回归时先调查故障原因；研究实验本身的统计推断由 experimental-analysis 承担。
