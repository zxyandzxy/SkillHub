# 用户任务、信息结构和界面状态

## 从任务到操作

先写清谁在什么场景进入界面、需要的信息、主要决定和完成后的结果。优先安排顺序与反馈，再选择卡片、标签页、弹窗或侧栏。页面样式与控件应遵循当前产品和平台惯例。

## 信息与视觉层级

使用准确标题、逻辑分组、清楚对齐、合适行宽与留白，让重要任务先被发现。颜色作为语义的一部分，但不可作为唯一信号。已有组件库提供配色、类型层级和间距时优先沿用；新增 token 应支持真实重复需求。

## 状态矩阵

按功能覆盖确实存在的初始、空、加载、处理中、完成、校验错误、系统错误、无权限、禁用、取消、离线、长内容和多设备场景。不是每个按钮实现全部状态；只检查该任务会出现的状态。

## 文案

按钮描述执行结果，错误解释什么失败和怎样继续，空状态说明原因和可执行入口。避免孤立“确定”“出错了”或内部异常类名。保护用户已经输入的数据，重要破坏性操作提供预防或恢复路径。
