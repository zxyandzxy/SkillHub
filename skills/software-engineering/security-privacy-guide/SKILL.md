# 软件安全与隐私保护

从实际资产、数据流和信任边界识别风险，选择与风险相称的控制，检查允许与拒绝路径。安全、隐私及合规结论需要不同依据。

## 明确资产与信任边界

检查当前功能涉及的用户、资源、数据类型、请求入口、客户端、后端、存储与外部服务；识别哪里跨越信任边界，谁能对哪个对象执行何种动作。写出具体错误或恶意行为可能造成的影响。

## 选择适用控制

1. **身份与对象权限**：身份认证不替代授权，可信服务端必须检查主体、资源和动作；隐藏前端按钮不能保护后端资源。
2. **输入与执行位置**：按 SQL、HTML、文件路径、命令、URL 等上下文分别采用校验、参数化、编码和路径限制，不能互相替代。
3. **秘密与依赖**：最小权限；不把令牌、密码、个人数据放入仓库或日志；发现泄露需评估撤销和轮换；依赖漏洞须核对版本和实际影响。
4. **隐私生命周期**：确认收集目的、最少字段、共享对象、外部模型或云服务传输、保留、备份、删除和用户控制。加密不能证明收集本身合理。

威胁—控制关系见 [threats-and-controls.md](references/threats-and-controls.md)。

## 负面验证与交付

依据风险设计未登录、权限不足、访问他人资源、输入攻击、泄露、共享撤销与删除等相应场景；在授权、安全环境内使用合成或脱敏数据进行验证。静态扫描无告警不能证明系统安全，没运行的检查不写为通过。隐私与验证细节见 [privacy-and-verification.md](references/privacy-and-verification.md)。

交付时说明受影响资产、实际威胁、采用的控制、验证结果与剩余风险。法律适用与高风险接受由有权限的人或专业人员决定。未经授权不得将私有代码或个人信息交给外部扫描、AI 或其他服务，也不得在生产环境执行破坏性测试。
