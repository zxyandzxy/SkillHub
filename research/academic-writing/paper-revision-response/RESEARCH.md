# 学术论文大修中的证据判断、正文修改与审稿回复

期刊大修与会议 Rebuttal 涉及多个相互依赖的判断。审稿意见可能指向研究设计中的实际缺陷，也可能源于定义分散、实验叙述不清或读者没有在正文找到作者已掌握的证据。处理意见之前，需要恢复审稿人真正提出的问题，核查论文相应版本，并判断什么证据足以回应。随后才能决定是否修改论文、补做分析、设计新的实验或仅在回复中澄清。

论文作者应对研究主张和正式修改作出决定。有效的协作方法应让作者看见原始意见、当前证据和修改代价，同时提供可直接核查的英文 LaTeX 草稿与清楚的中文解释。回复信的可靠性还取决于一个容易被忽视的约束：文中宣称“已经修改”“已经补充实验”的动作，必须在正式稿件与实验记录中真实发生。

## 一、先把审稿意见还原为能够回答的科学问题

评论的字面建议和科学关切并不一定相同。审稿人建议增加一个新的 Benchmark，可能是因为担心原有评测缺乏任务多样性；要求提供不同模型结果，可能实际上在质疑效果是否来自模型能力而不是方法本身。直接执行每条表面建议，会在没有明确研究必要性时不断扩大实验范围。

处理每条意见，应先保存完整原文及原编号，再区分事实判断、疑问、建议和例子。若一句评论同时质疑数据真实性与结果泛化，需要分别建立对应证据。接着在被审论文的真实版本中定位作者已经写出的定义、实验或结论。一个概念出现在正文，并不意味着普通读者能够顺利找到足以回答问题的完整解释。

例如审稿人认为“作者没有解释样本的选择”，现有论文可能在 Dataset 一节给出来源，在 Threats 一节给出过滤规则。此时最有价值的改变可能是将关键纳入与排除条件组织到读者第一次需要的位置，而不是重新收集数据。若纳入规则确实未记录，必须由作者补充真实协议；语言改写无法证明数据有效。

## 二、根据证据缺口决定处理方式

一项意见的处理方法至少涉及以下判断：论文已有的证据能否直接回答；问题是否只是阅读定位；能否用现有逐任务结果完成分析；是否需要补充受控实验；是否应收窄正文的主张。几条意见可能共享同一缺口，例如测试有效性与评测基准公平性可能都需要核查数据划分。可以合并调查，但最终回复要逐条对应原编号，不让某个子问题遗漏。

对量化质疑，原始预测、任务 ID、模型配置、评分脚本、每项测量与汇总值属于不同证据层次。只有汇总均值时，不能补造配对统计量或显著性。只有单次模型输出时，不能断言多次运行稳定。人工标注需要真实标注人员、样本抽样规则和争议处理，AI 生成标签不能被称作独立人工验证。

补充实验的科学价值来自它能否影响具体结论。例如 reviewer 质疑方法在小规模仓库之外是否有效，补充一个按仓库规模分层的分析可能比无差别地重复所有实验更直接；但前提是已有数据能支持这样的分层，而且分层单位与比较协议合理。若核心主张本来只覆盖特定数据集，在正文明确范围也可能是合理处理。作者应根据实际研究目标、成本与证据选择，而不是按评论条数等量增加实验。

## 三、公开审稿案例：MemoryAgentBench 的范围问题

*Evaluating Memory in LLM Agents via Incremental Multi-Turn Interactions*（MemoryAgentBench）的公开评审材料中，审稿人提出过任务主要集中在语言问答或摘要、缺少工具执行和软件工程场景的质疑。有关原始评论及作者回复可在[公开评审档案](https://cseweb.ucsd.edu/~jmcauley/reviews/iclr26c.pdf)中查阅。

这一意见实际在问：使用语言交互评估长期记忆的结果，能否推广到需要规划与外部动作的 Agent？问题涉及**外部效度**，不必然意味着现有文本任务没有价值，也不能简单声称这些文本任务足以代表所有交互场景。

面对同类意见，处理时应先定位论文中关于任务范围的原始主张，判断是否将“测量记忆能力”扩大表述成“覆盖各种行动型 Agent 任务”。如研究本身没有工具执行实验，应明确定义已测试场景，并解释行动型任务还涉及规划、工具访问与环境反馈等其他变量。是否新增实验由作者根据研究主张与资源确定；没有运行的实验不能写进回复信的已完成事项。

### 先前知识的替代解释

同一公开评审还询问测试时学习的效果是否来自给定的上下文，还是模型原有知识。原作者公开报告的 GPT-4o-mini 两组设置中，多类别分类任务得分分别是无历史示例 0.6、提供上下文 82.0；电影推荐任务为 6.1 与 15.1。这些数字来自[原作者公开答复](https://cseweb.ucsd.edu/~jmcauley/reviews/iclr26c.pdf)，不是本研究重新运行的结果。

这两个对照有具体意义：它们支持所测试配置中上下文与性能差异相关的判断。但没有报告重复运行方差，就不能自行推导配对统计显著性；两个任务的评分指标也不能不加说明地混合。学术回复应清楚说明“作者报告了哪些条件和数值、这些数值说明什么、仍不能排除什么”，而不是只说“补充实验充分证明我们的观点”。

这两类意见展示了不同处理方式：一类需要澄清任务的适用范围，另一类需要定向解释对照实验。它们都要求将审稿人的科学问题与稿件中的证据关系先建立起来，才能写出可信回复。

## 四、作者如何核查拟议的正文修改

对于论文正文，修改前后对照应保持真实的 LaTeX 来源。`.tex` 中的 `\cite{}`、`\ref{}`、`\label{}`、数学公式环境与自定义宏承担引用、数学和版面语义。改写时删除或伪造这些命令，可能改变论文的事实引用，或使代码无法编译。若手中只有 PDF，可以说明可观察的现有文字，却不能将 PDF 中的句子伪装为原始 LaTeX 源码。

作者审阅实质性段落时，最有价值的信息是：当前段落所在位置、原文完整 LaTeX、原文准确译文、修改后完整 LaTeX、修改后准确译文，以及实际改变了什么研究信息。若新增段落没有原文，应直接注明，不能构造一个“修改前版本”。当修改影响新的实验解释、创新定位或方法定义，作者必须知道这些后果并明确选择。

论文修改追求解决真实读者理解问题。对一个方法定义，可能只需要把分散在 Implementation 的参数说明移到首次出现的位置；对一个结果结论，则可能需要同时更新摘要、Results、图表和 Discussion 的数值。修改的范围由依赖关系决定，不按固定篇幅目标把充分的方法描述一律移到附录。

## 五、审稿回复信的事实契约

回复信负责把意见、证据、修改和定位连接起来。一段完整回复应让审稿人直接知道答案、凭什么得出答案，以及实际修改位于何处。引用论文已写出的内容时，应提供准确章节、表格或附录位置；需要补充工作的，必须区分已发生的动作与尚待作者批准的计划。

例如，“We have conducted additional experiments” 是可核查的完成声明：需要相应实验配置、原始结果和正文位置支持。若目前只设计了实验，应写成建议或拟定工作；草稿阶段可以在作者审批后调整措辞，但不能提前把拟稿用完成时态写成事实。对于有合理科学争议的意见，回复可以礼貌地陈述研究范围和依据，无须无条件承认审稿人的每一项假设。

多条评论完成后，需要再次核对：每条原始问题是否有答案，回复中的页码和图表是否在当前稿件存在，新增统计数据是否与表格一致，LaTeX 标签和引用是否正确，以及修改是否引入了与其他章节的矛盾。最终稿件、回复信和补充材料应能够分别追溯到同一组已确认的研究事实。

## 六、研究结论如何形成 `paper-revision-response` Skill

审稿意见处理的专业核心是“理解真实质疑—核查现有论文与证据—选择必要修改—作者审阅—执行与回复一致性”。[SKILL.md](../../../skills/academic-writing/paper-revision-response/SKILL.md) 依此组织任务，不把所有评论强制转换为新增实验或正文重写。

| 研究认识 | Agent 的动作 | 对应文件 |
| --- | --- | --- |
| 审稿意见包含事实、担忧和建议（第一节） | 读取完整原文、分解实质子问题并核查原稿 | [comment-decisions.md](../../../skills/academic-writing/paper-revision-response/references/comment-decisions.md) |
| 修改策略取决于证据缺口（第二节） | 比较澄清、调整表述、已有数据分析、新实验与主张收窄等路径 | [comment-decisions.md](../../../skills/academic-writing/paper-revision-response/references/comment-decisions.md) |
| 对照需要可追溯原始数据与统计单位（第二、三节） | 先核对原始记录、配置、分母和分析证据，保留未验证范围 | [supplementary-evidence.md](../../../skills/academic-writing/paper-revision-response/references/supplementary-evidence.md) |
| 作者应看见真实修改及全文影响（第四节） | 提供完整的原/改 LaTeX 和准确中译，记录作者批准状态 | [revision-collaboration.md](../../../skills/academic-writing/paper-revision-response/references/revision-collaboration.md) |
| 回复信中的完成时态应匹配实际动作（第五节） | 按原审稿编号回答，给出证据、执行状态和准确位置 | [response-letter.md](../../../skills/academic-writing/paper-revision-response/references/response-letter.md) |
| 多处修改会产生一致性风险（第五节） | 核对正文、附录、图表、回复与状态记录 | [final-consistency.md](../../../skills/academic-writing/paper-revision-response/references/final-consistency.md) |

核心入口保存适用于所有审稿处理的路由和权限边界；五份参考文件按当前问题加载。日常论文写作由 `academic-writing` 承担，独立审稿由 `independent-paper-review` 承担，结果重新统计应遵循实际科研协议。此分工使审稿处理围绕作者的真实证据开展，避免把回复信的语言完整性误当成科学问题已经解决。
